# Оформление билетов на мероприятие

Тестовое задание SQOCH «Тест 01 / Код и интерфейс». Это рабочий сценарий от выбора события до результата: успешный заказ или «места закончились». Вёрстка адаптивная, от 360 px до десктопа.

- **Фронтенд:** React 18, TypeScript, Vite, Tailwind CSS 4, React Router
- **Бэкенд:** Python 3.12, FastAPI, Pydantic 2, httpx
- **Интеграция:** афиша KudaGo (публичное API без ключа)

Демо-видео: [`docs/demo-desktop.mp4`](docs/demo-desktop.mp4) (успешный заказ, редактирование) и [`docs/demo-mobile.mp4`](docs/demo-mobile.mp4) (360 px: ошибки правил, «места закончились», переоформление на другую дату).

## Запуск

### Docker

Один образ: FastAPI отдаёт и API, и собранный фронтенд.

```bash
docker compose up --build
# http://localhost:8080
```

### Локально

```bash
# API, порт 8000
cd backend
uv sync
uv run uvicorn app.main:app --reload

# Фронтенд, порт 5173; /api проксируется на 8000
cd frontend
npm install
npm run dev
```

Переменные окружения API (см. `backend/.env.example`):

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `EVENTS_SOURCE` | `kudago` | `kudago` — живая афиша с откатом на демо; `mock` — только демо-афиша |

### Тесты и проверки

```bash
cd backend && uv run pytest && uv run ruff check app tests   # 11 тестов
cd frontend && npm test && npm run typecheck && npm run build
```

## Сценарий

1. **Афиша.** Город, дата, категория. В карточке видны цена, ближайшая дата и остаток мест.
2. **Мероприятие.** Шаги на одной странице:
   1. дата и время;
   2. участники, от 1 до 4: имя и возраст;
   3. email, один на заказ.

   Справа (на телефоне — в нижней панели) живой состав заказа и итог.
3. **Проверка заказа.** Все данные на одном экране, у каждого блока есть кнопка «Изменить». Данные сохраняются.
4. **Результат.**
   - Успех: номер заказа и билет на каждого участника.
   - «Места закончились»: сервер вернул 409. Показываем, сколько мест осталось, и предлагаем варианты: тот же заказ на другую дату в один клик, оставить столько участников, сколько есть мест, или выбрать дату вручную.

### Как показать «места закончились»

В демо-афише есть сеансы с 2–3 местами: например, «Фестиваль науки», ближайшая дата, 2 места.

1. В первой вкладке заполните заказ на двоих и дойдите до «Проверьте заказ».
2. Во второй вкладке купите один билет на тот же сеанс.
3. Вернитесь в первую вкладку и нажмите «Подтвердить заказ».

Это настоящая гонка за места: сервер списывает их атомарно. Отдельного переключателя «сломать» нет.

## Правила и как я их понял

| Правило | Реализация |
|---|---|
| Полный билет 2 000 ₽ с 14 лет, детский 1 000 ₽ до 14 | Тип билета определяется по возрасту автоматически и сразу показан в карточке участника |
| Ребёнок только с участником от 18 лет в том же заказе | «Ребёнок» — участник младше 14 лет. Подростки 14–17 лет могут прийти одни: у них полный билет, и правило про детей к ним не относится |
| 1–4 участника | Кнопка «Добавить» неактивна на 4 участниках и когда на сеансе не осталось мест |
| Имя и возраст у каждого, email один на заказ | Ошибки поля показываются после ухода из поля или после попытки продолжить. При ошибке страница прокручивается к первому неверному полю |
| Возрастной ценз события (например, 18+ из KudaGo) | Дополнительное правило: участник младше ценза не пройдёт проверку |

Правила описаны дважды: `backend/app/rules.py` и `frontend/src/lib/rules.ts`. На фронте — для мгновенной подсказки, на сервере — как источник истины. Сервер всегда проверяет заказ заново и отвечает 422 со списком нарушений.

## Архитектура

```
backend/app
  rules.py           чистые правила заказа (цены, состав, возраст)
  inventory.py       остатки мест и заказы: атомарное списание под asyncio.Lock, идемпотентность
  providers/events.py   KudaGo → нормализация → кэш 10 мин → откат на моки
  routers/           /api/events, /api/orders
  main.py            в образе также раздаёт собранный фронтенд
frontend/src
  lib/rules.ts       те же правила + тесты
  lib/api.ts         типизированный клиент, ApiError со статусом
  components/Checkout.tsx   состояние оформления: form → review → done | soldout
```

- **Места.** Учёт в памяти процесса. В production это одна строка в PostgreSQL: `UPDATE … SET seats_left = seats_left - n WHERE seats_left >= n RETURNING`. Тест `test_race_for_last_seats` запускает 5 параллельных заказов на 3 места и проверяет, что прошёл ровно один.
- **Идемпотентность.** Повторная отправка (двойной клик, ретрай сети) не создаёт второй заказ: заголовок `Idempotency-Key` обновляется при любом изменении данных.
- **KudaGo** отвечает не из всех стран: из песочницы вне РФ запросы получали 403. В таком случае API показывает демо-афишу, и интерфейс прямо пишет об этом. KudaGo не отдаёт количество мест, поэтому для его сеансов остаток генерируется детерминированно из id сеанса: часть сеансов почти распродана.

## CI и деплой

`.github/workflows/ci.yml` на каждый push:

1. **test** — ruff и pytest для бэкенда, vitest и сборка для фронтенда.
2. **deploy** — собирает Docker-образ, по SSH копирует его на сервер и перезапускает через `docker compose`, затем проверяет `/api/health`.

Деплой включается, когда в настройках репозитория (Settings → Secrets and variables → Actions) заданы секреты:

| Секрет | Что это |
|---|---|
| `SSH_HOST` | IP или домен сервера |
| `SSH_USER` | пользователь с доступом к Docker |
| `SSH_KEY` | приватный ключ, публичная часть — в `~/.ssh/authorized_keys` на сервере |
| `SSH_PORT` | необязательно, по умолчанию 22 |

Порт приложения задаётся переменной `APP_PORT` (по умолчанию 80). На сервере нужны только Docker и плагин compose. Сервер лучше брать в РФ: тогда KudaGo отдаёт живую афишу.

## Затраты и что не сделано

Фактическое время: _указать_.

Не сделано или упрощено:

- нет настоящей оплаты и отправки писем;
- хранение в памяти: после перезапуска API места сбрасываются;
- нет удержания мест на время оформления: свободность проверяется при подтверждении, и это осознанно, ведь именно так появляется сценарий «места закончились»;
- нет e2e-тестов в CI: сценарий прогонялся Playwright-скриптом локально, из него записаны видео;
